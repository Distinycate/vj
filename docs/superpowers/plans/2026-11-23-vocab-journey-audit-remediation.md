# Vocab Journey Audit Remediation Implementation Plan

> **สำหรับผู้รับช่วง:** ใช้ `executing-plans` ดำเนินการทีละงานตามลำดับด้านล่าง แต่ละงานต้องมี regression test และตรวจผลก่อนเริ่มงานถัดไป

**เป้าหมาย:** แก้ปัญหาที่พบในการตรวจ Vocab Journey โดยรักษารหัสเข้าเกมปัจจุบัน ข้อมูลเดิม และระบบที่ไม่เกี่ยวข้อง

**แนวทาง:** แยก hotfix ข้อมูลสาธารณะออกจากงานฐานข้อมูล ใช้ transaction กับการบันทึกคะแนนและการจ่ายรางวัล ทดสอบแต่ละส่วนบนเครื่องและฐานข้อมูลทดสอบก่อนเผยแพร่

**ระบบ:** Next.js App Router, React, Supabase/PostgreSQL, Node test runner และ browser tests บนข้อมูลจำลอง

**อ้างอิง:** ผล audit ในแชต 23 พ.ย. 2569 และแผนเดิม [Assessment Season Reset](2026-11-04-assessment-season-reset.md) แผนนี้ใช้สถานะโค้ด ณ `e06b14d` พร้อมงานค้างใน working tree เป็นจุดตั้งต้น ให้ตรวจ diff ปัจจุบันอีกครั้งก่อนลงมือ

## ขอบเขตที่ห้ามเปลี่ยน

- **รหัสเข้าเกมเดิมต้องใช้ได้เหมือนเดิม** ไม่เปลี่ยน Username, รหัสผ่าน/PIN, รูปแบบรหัส, ค่าเริ่มต้นของบัญชีใหม่ หรือนโยบายบังคับตั้งรหัสใหม่ ไม่หมุนรหัสหรือเขียนทับรหัสของนักเรียนเดิมในงานนี้
- การย้ายไฟล์ออกจากเว็บ การหยุดเก็บรหัสจริงในเบราว์เซอร์ และการแก้ session เครือข่าย ไม่ใช่การเปลี่ยนข้อมูลล็อกอิน: ช่องจดจำเก็บได้เพียงชื่อผู้ใช้ โดยไม่เพิกถอน session ปัจจุบันในวงกว้าง หากผลตรวจชี้ว่าไฟล์เคยเปิดบนเว็บจริง ให้รายงานแยกตามข้อเท็จจริงและขอให้ผู้ดูแลตัดสินใจเรื่องรหัสในงานถัดไป
- ไม่ลบผลสอบ ประวัติด่าน เหรียญ ตั๋ว การ์ด Rank, XP หรือ SRS และไม่รวมบัญชีที่ชื่อซ้ำ ห้ามนำข้อมูลนักเรียนจริงมาเป็น fixture หรือใส่ใน log
- ไม่แตะงานสอน/Grammar/O-NET ที่กำลังแก้โดยไม่จำเป็น และไม่เขียนทับการแก้ไขใน working tree
- เทอม 2/2569 เริ่ม **1 พ.ย. 2569 เวลาไทย** แต่รอบเรียนใหม่เริ่มเมื่อกดเปิดจริง เป็นคนละขอบเขตเวลา รีเซ็ตเฉพาะนักเรียนภายในที่เปิดใช้งาน ไม่รีเซ็ต Team Battle, บัญชีภายนอก หรือบัญชีปิด
- ห้ามนำ schema migration กับคำสั่งรีเซ็ตจริงมารวมเป็นคำสั่ง deploy เดียวกัน ห้ามรัน SQL หรือ deploy ในขั้นจัดทำแผน

## ลำดับงานและเกณฑ์ผ่าน

### 1. P0 — ปิดไฟล์ข้อมูลที่เปิดโดยไม่ล็อกอิน

**จุดแก้:** `public/students_season2_summary.csv`, `scripts/build_students_season2.py`, `src/app/api/admin/students/import-season/route.ts`, `src/app/api/admin/term-one-report/route.ts` และไฟล์ต้นทางที่อ้างถึง

- [ ] สร้าง regression test ที่ตรวจจาก HTTP status ว่าไฟล์เดิมเปิดไม่ได้โดยไม่ล็อกอิน และตรวจ artifact ว่าไม่มี roster หรือ snapshot ดิบใน browser bundle/public static assets
- [ ] ย้ายข้อมูลดิบไปพื้นที่จำกัดสิทธิ์ ปรับสคริปต์ไม่ให้สร้าง roster ใน `public/` อีก ให้รายงานส่งเฉพาะฟิลด์ที่ใช้งานจริง แยกข้อมูลสำรองออกจากโค้ดโดยรักษาความสามารถดูรายงานเทอม 1
- [ ] ก่อนปล่อย: ทดสอบหน้าเดิมและรายงานเทอมเก่า หลังปล่อย hotfix: ตรวจเฉพาะ header/status ของ URL ปัจจุบันและ deployment เก่าที่ผู้ดูแลระบุ ถ้าเคยเปิดจริง ให้บันทึกผลและจำกัดการเข้าถึง deployment เก่าตามขอบเขตที่อนุมัติ ไม่เปลี่ยนรหัสนักเรียนหรือ rewrite Git history เอง
- [ ] เกณฑ์ผ่าน: URL ที่เคยเปิดไฟล์ไม่คืนไฟล์อีก และบัญชีเดิมเข้าสู่เกมด้วยข้อมูลเดิมได้

### 2. P1 — Session เครือข่ายและนำเข้ารายชื่อโดยไม่ทับบัญชี

**จุดแก้:** `src/app/page.tsx`, `src/app/register/network/page.tsx`, `src/app/api/network/auth/login/route.ts`, `src/app/api/admin/students/import-season/route.ts`

- [ ] ทำเส้นทางล็อกอินเครือข่ายผ่าน API ที่สร้าง session cookie แล้วโหลดโปรไฟล์โดยใช้ session นี้ จัดรูปข้อมูลให้ตรงกับ store เดิม ทดสอบล็อกอิน → เข้าเกม → refresh ทั้งมือถือ/PC และไม่สลับบัญชีภายในกับเครือข่าย
- [ ] จดจำเฉพาะชื่อผู้ใช้ ล้างช่องรหัสเดิมจากข้อมูลที่แอปเก็บไว้ในเบราว์เซอร์ อนุญาตให้ใช้ password manager ของเครื่องตามปกติ
- [ ] แยกนำเข้าเป็น preview และ apply: ถ้า Username กับรหัสนักเรียนชี้คนละบัญชี ต้องหยุดและแสดงรายการขัดแย้งก่อนเขียนข้อมูล บัญชีเดิมห้ามปรับรหัส ห้ามเปิดบัญชีที่ปิดเอง และไม่เปลี่ยนห้อง/เทอมโดยไม่มีรายการยืนยัน ป้องกันกดซ้ำและจำกัดสิทธิ์ apply
- [ ] เกณฑ์ผ่าน: จำลองบัญชีเดิมและข้อมูลชนกัน ตรวจว่ารหัสเดิมไม่เปลี่ยน และบัญชีนอกโรงเรียนไม่หลุดเข้า leaderboard, Team Battle หรือ Gacha ของโรงเรียน

### 3. P1 — คะแนน Pre/Post-test และการเปิดรอบใหม่

**จุดแก้:** `src/app/api/student/assessment/route.ts`, `src/lib/server/assessmentProgress.ts`, `src/hooks/useAssessmentSubmission.ts`, `src/components/{PreTest,PostTest,Dashboard}.tsx`, `supabase/migrations/20261104050458_assessment_season_atomic_reset.sql`, `scripts/test-assessment-season.mjs`

- [ ] ยืนยัน schema ที่ติดตั้งจริงด้วย query อ่านอย่างเดียว ถ้า migration เคยรันแล้ว ให้แก้ด้วย migration ถัดไป ไม่แก้ไฟล์ SQL ที่ applied แล้ว
- [ ] ใช้ `submit_assessment_v2` สำหรับผลจริง รับ `epoch` และ `submissionId` จากชุดข้อสอบ ตรวจตัวตนจาก session และคืน 409 ให้แท็บข้ามฤดูกาล ไม่ fallback ไปเขียนหลายตารางแยกกัน ให้ DB ยืนยันก่อนแสดงผลสำเร็จ
- [ ] เก็บคะแนนทศนิยมและรอบสอบจริง แก้ summary จากประวัติโดยไม่สร้างคะแนนหรือเปลี่ยนด่านตามคะแนน ทดสอบ 14, 13, 13, 15, 9 → 12.8, คะแนนศูนย์จริง, บันทึกซ้ำ, การเขียนสรุปล้มเหลว และ 5 รอบเสร็จแล้วเข้า Stage 1
- [ ] เพิ่ม checkpoint สำหรับ Post-test แบบไม่บังคับ หลังด่าน 10, 20, …, 100 ตรวจจากด่านที่ผ่านจริงและเก็บคู่กับฤดูกาลเดิมของผลสอบ แถวเก่าที่ไม่มี checkpoint ให้ขึ้นว่าไม่ระบุ ไม่เดาย้อนหลัง
- [ ] ทดสอบ reset เฉพาะ fixture: archive แล้วจึงเปิดรอบใหม่ใน transaction เดียว กดซ้ำไม่ล้างงานใหม่ บัญชีภายนอกและสินทรัพย์ไม่เปลี่ยน สรุปนโยบายรางวัลผ่านครั้งแรกหลังรีเซ็ตให้ผู้ดูแลยืนยันก่อนเปิดจริงโดยไม่แตะยอดคงเหลือเดิม

**จุดแก้:** `src/app/api/game/complete/route.ts`, `src/app/api/game/start/route.ts`, `MIGRATION_GAME_PROGRESSION_V3.sql` และ migration เพิ่มเติมตามสถานะจริง

- [ ] เกณฑ์ผ่าน: ผ่านครั้งแรกได้รางวัลครั้งเดียว เล่นย้อนหลังและปรับดาวได้ตามกฎเดิม ผลหน้าเกมตรงกับ Dashboard หลัง refresh และนักเรียนภายนอกไม่ปะปนเศรษฐกิจโรงเรียน

- [ ] ใช้กฎปลดล็อกและสถานะกิจกรรมเดียวกันทั้งเปิดข้อสอบและรับผล แสดงสถานะบันทึกที่ตรวจสอบได้ ไม่ข้ามด่านหรือเขียนผลในกิจกรรมปิดแล้ว คงสิทธิ์เพิ่มนักเรียนตามห้องของครูผู้มีสิทธิ์
- [ ] เกณฑ์ผ่าน: เปิดฤดูกาลล้มเหลวแล้วฤดูกาลเดิมยังอยู่ ปิดซ้ำไม่แจกรางวัลซ้ำ คะแนนกับรางวัลระดับห้องไม่ข้ามห้อง ด่านล็อกถูกปฏิเสธโดยไม่สร้างผลสอบ และ workflow การ์ดเดิมทำงานครบ

**จุดแก้:** `src/app/api/admin/{school-overview,school-term-words,students,onet}/route.ts`, `src/components/admin/{TermArchiveTab,RemedialEventManager,IndividualStudentProfile}.tsx`, `src/app/api/events/runs/route.ts`

- [ ] ทำแหล่งกำหนดเทอมกลางและกำหนด mapping สำหรับรหัสเทอมเก่าโดยตรวจข้อมูลจริง ไม่ย้ายแถวเพียงเพราะป้ายใน UI เก่า กรองห้อง กลุ่มนักเรียน และเทอมให้ตรงกันในทุก KPI และกราฟ รวมถึงรายการคำผิดบ่อย
- [ ] คงคะแนนศูนย์จริง แสดง “ยังไม่สอบ” เมื่อไม่มีข้อมูล และคำนวณ Learning Gain จาก Pre/Post ของคนและรอบที่จับคู่กันได้ แสดงผลก่อนเปิดรอบใหม่แยกจากเทอม 1
- [ ] รวมผลในฐานข้อมูลหรืออ่านแบบแบ่งหน้าตามปริมาณข้อมูล แทนการตัดจำนวนแถวเงียบ ๆ วัด latency ก่อน/หลังของการดูรายบุคคลและภาพรวมด้วย fixture ชุดเดียวกัน ทดสอบกรณีวันตัดเทอมเวลาไทยและข้อมูลเกินเพดาน query
- [ ] เกณฑ์ผ่าน: Admin สลับเทอมได้ ผลสองเทอมไม่ปน, ไม่มีข้อมูลโรงเรียนเครือข่ายในสถิติโรงเรียนหลัก และรายงานไม่แสดงค่าเป็น 0 เมื่อโหลดล้มเหลว

## เกณฑ์ปล่อยและการกู้คืน

- [ ] คงสถานะเครื่องมือพื้นฐานที่ผ่านจาก audit (`npm run typecheck`, `npm run lint`, `git diff --check`) และรัน `npm test`/production build ให้ผ่าน พร้อมแนบผล SQL integration และ browser tests รอบล่าสุด
- [ ] โยก hotfix ปิดข้อมูลออกเป็นชุดแรกได้ ส่วนงานที่ต้องใช้ SQL ให้ยืนยันสิทธิ์ Supabase โปรเจกต์ Vocab Journey ตรวจ schema/backup/สิทธิ์ RPC บน staging และยืนยันว่า migration แบบเพิ่มโครงสร้างไม่รีเซ็ตข้อมูลเอง
- [ ] ติดตั้ง schema ที่รองรับก่อน deploy โค้ดที่เรียก RPC จากนั้น smoke-test ล็อกอินด้วยรหัสเดิมและตรวจรายงาน เมื่อผู้ดูแลเลือกช่วงหยุดใช้งานและยืนยันให้เปิดรอบจริง จึงเรียก reset ครั้งเดียว แล้วเทียบจำนวน archive กับจำนวนผู้เข้าร่วม ด่าน 1, จำนวนรอบ Pre-test ใหม่ และยอดคงเหลือ
- [ ] หากยังไม่เปิดรอบใหม่ ให้ย้อนเฉพาะโค้ดที่ไม่ทำให้ไฟล์ข้อมูลสาธารณะกลับมา หากเปิดรอบแล้วให้หยุดเขียนและสำรองข้อมูลหลังเปิดรอบ ก่อนกู้เฉพาะรายการจาก archive ด้วย transaction ที่ผู้ดูแลตรวจ ไม่เขียนทับผลใหม่ทั้งระบบ

**ขอบเขตของเอกสารนี้:** จัดทำแผนเท่านั้น ยังไม่มีการแก้โค้ดผลิตจริง เปลี่ยนรหัส รีเซ็ตข้อมูล หรือ deploy

## บันทึกการลงมือ

- P0: ย้าย CSV, roster, SQL ที่มีข้อมูลรายคนและ snapshot ไปที่ `backups/private-rosters/` ซึ่งถูก Git ignore; repository เป็นสาธารณะ จึงต้องตั้ง `TERM_ONE_REPORT_JSON` ฝั่งเซิร์ฟเวอร์จากไฟล์ส่วนตัว `term-one-report.json` ที่สรุปจากต้นฉบับโดยตรง; ตรวจ URL เดิมบน localhost เป็น 404 แล้ว deployment เก่าและ Git history ยังต้องตรวจแยก
- P1 Session: หน้า Guest ใช้ session API และคงประเภท EXTERNAL เมื่อ refresh; ทั้งสองหน้าจดจำเฉพาะ Username โดยไม่เปลี่ยนรหัสบัญชี
- P1 นำเข้า: แอดมิน preview ก่อน apply, หยุดเมื่อชน/ห้องไม่ชัด, ข้ามบัญชีเดิม และเพิ่มบัญชีและ learning path ใหม่พร้อมกัน ใช้ `SEASON_ROSTER_JSON` แบบ server-only และต้องติดตั้ง migration `20261123160536_import_new_students_without_reset.sql` ก่อนเปิดใช้ปุ่มนำเข้า ห้าม commit roster ดิบหรือใส่ค่าในตัวแปร NEXT_PUBLIC
- P1 การประเมิน: เชื่อม API กับ `submit_assessment_v2` และเพิ่ม Post-test หลัง checkpoint ที่ผ่านจริง (เลือกทำได้) **ห้าม deploy จนกว่าจะยืนยัน RPC, assessment_epoch และ post_tests.stage_checkpoint ใน Supabase เป้าหมาย** การติดตั้ง schema ไม่ใช่การเปิดรอบใหม่; รอบนี้ไม่ได้เปิดรอบจริง
- P1 แก้ 0/ร: เปิดและส่งผลด่านใช้กฎสิทธิ์เดียวกัน จำกัดที่ด่านในชุดกิจกรรมที่เปิดอยู่ และตรวจ error การเขียนก่อนแจ้งผลสำเร็จ ยังไม่ได้ย้ายยอดกิจกรรมเข้า transaction เดียว
- จบด่านและเหรียญ: ใช้ V3 transaction ทางเดียว ตัดทางสำรองที่เขียนแยก ตรวจ V3 ใน staging/production ก่อน merge เข้า main
- Team Battle: เปิด/ปิดแบบ atomic, เฉพาะแอดมิน, แยกห้อง, รักษาจำนวนรางวัลเดิมและไม่ใช้การ์ดที่ถูกจอง ทดสอบการกดซ้ำ; ตรวจสถานะฤดูกาลที่อาจเคยจ่ายบางส่วนจากระบบเก่าก่อนปิดจริง
- รายงาน: Pre/Post และกราฟแยกเทอมเวลาไทยและคงคะแนน 0 จริง ส่วน Accuracy/Rank ภาพรวมเป็นข้อมูลสะสมและระบุชัด ไม่เปลี่ยนรหัสเทอมของนักเรียนหรือสถานะกิจกรรม
- Listening/Context: ใช้ config กลางในเกมหลัก, คำซ้ำไม่บิดเฉลย และรักษาโหมดเครือข่าย/Skull ไว้ เกมยังใช้ข้อมูลเฉลยเพื่อ feedback ทันทีฝั่ง client; การเอาเฉลยออกจาก payload ทั้งหมดต้องย้าย feedback และไอเทมช่วยตอบไปให้เซิร์ฟเวอร์คำนวณก่อน
